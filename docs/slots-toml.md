# slots.toml -- ECC Algorithm Disambiguation

`slots.toml` tells `onlykey-pkcs11` and `onlykey-vcard` which algorithm each OnlyKey ECC
slot holds. It is required because the `OKGETPUBKEY` command does not return algorithm
metadata -- the response length is the only distinguishing signal available from the device.

## Why disambiguation is necessary

The OnlyKey HID protocol returns raw public key bytes for each slot:

| Response length | Possible algorithms |
|----------------|---------------------|
| 32 bytes | Ed25519 **or** Curve25519 |
| 64 bytes | NIST P-256 **or** secp256k1 |
| 256 bytes | RSA-2048 (modulus only, public exponent is always 65537) |
| 512 bytes | RSA-4096 (modulus only, public exponent is always 65537) |

Within each length class, the bytes are indistinguishable without prior knowledge of which
key type was loaded. Ed25519 and Curve25519 keys are both 32-byte Edwards/Montgomery curve
points. P-256 and secp256k1 keys are both 64-byte uncompressed Weierstrass coordinates
(without the 0x04 prefix).

## Expected use cases by algorithm

| Algorithm | Typical use |
|-----------|-------------|
| Ed25519 | OpenPGP signing (Sig key), SSH authentication |
| Curve25519 | OpenPGP decryption (Dec key via ECDH), X25519 key agreement |
| NIST P-256 | PIV Authentication (9A), PIV Digital Signature (9C), PIV Card Auth (9E), TLS client auth |
| secp256k1 | Cryptocurrency signing, Bitcoin/Ethereum use cases |
| RSA-2048 | Legacy enterprise PKI, S/MIME, older TLS client auth |
| RSA-4096 | High-assurance certificate signing |

## `generate-config` behavior for ambiguous slots

The `onlykey-tool generate-config` subcommand queries each slot and writes a draft
`slots.toml`. When it encounters a slot whose key length is ambiguous (32 bytes or
64 bytes), it:

1. Marks the slot `algorithm = "unknown"` in the output file
2. Prints a warning to stderr naming the slot numbers that need manual disambiguation
3. Continues processing the remaining slots

Example warning output:

```
warning: slot 101 is ambiguous (32-byte key could be Ed25519 or Curve25519) -- set algorithm manually in slots.toml
warning: slot 104 is ambiguous (64-byte key could be NistP256 or Secp256k1) -- set algorithm manually in slots.toml
```

Example draft output for an ambiguous slot:

```toml
[[slot]]
slot = 101
algorithm = "unknown"  # TODO: set to "Ed25519" or "Curve25519"
label = "OnlyKey ECC 101"
id = "101"
```

## Completing the configuration after `generate-config`

Edit each `algorithm = "unknown"` entry to one of the supported values:

| TOML value | Meaning |
|------------|---------|
| `"Ed25519"` | EdDSA signing key (32-byte compressed Edwards point) |
| `"Curve25519"` | X25519 ECDH key (32-byte Montgomery point) |
| `"NistP256"` | ECDSA / ECDH on NIST P-256 (64-byte uncompressed point) |
| `"Secp256k1"` | ECDSA on secp256k1 (64-byte uncompressed point) |
| `"Rsa2048"` | RSA-2048 signing and decryption |
| `"Rsa4096"` | RSA-4096 signing and decryption |

## Missing entries

If a slot is not listed in `slots.toml`, it is silently skipped during enumeration. A
warning is printed to stderr:

```
warning: slot 108 has a key but no entry in slots.toml -- slot skipped
```

This is intentional: a partially configured device still exposes the slots it can without
failing initialization.

## Example `slots.toml`

```toml
# OnlyKey slot configuration
# Generated by: onlykey-tool generate-config
# Edit algorithm = "unknown" entries before use.

[[slot]]
slot = 101
algorithm = "Ed25519"
label = "GPG Signing Key"
id = "101"

[[slot]]
slot = 102
algorithm = "Curve25519"
```
